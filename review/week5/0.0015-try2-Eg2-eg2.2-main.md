## Issues

### Critical

**1. No Error Handling**

```go
server.ListenAndServe()  // Error ignored
```

Fourth file in a row without error handling. At this point, this is a pattern you're reinforcing, not a one-off mistake.

**Production code would crash silently if port 80 is already in use.** You wouldn't know why the server failed to start.

### Major

**1. Port 80 Requires Root/Admin Privileges**

Your comment says:

```go
// Now this server is listening in port 80 or simpally localhost it self
```

**This is misleading.** On macOS/Linux, binding to port 80 requires `sudo`. If you run this without elevated privileges, it will fail with "permission denied". You didn't test this, did you?

Expected behavior:

```bash
$ go run main.go
# listen tcp :80: bind: permission denied (no output because error is ignored!)
```

**2. Spelling Errors**

- "simpally" → "simply"
- "lest" → "let's"

Only 2 errors (improvement continues), but "simpally" has appeared in every file this week. This suggests you're not re-reading your code before committing.

**3. Comment Reference Typo**

```go
// Till now w have only looking into GET request, lest look into PUT in try3_POST/main.go
```

- "w have" → "we have"
- "looking into" → "looked at"
- "lest look into PUT" → "let's look at POST"

**Also: You wrote PUT but the folder says POST.** These are different HTTP methods:

- POST creates resources
- PUT updates/replaces resources

The folder is named `try3_POST`, so you meant POST, not PUT. This is a conceptual error, not just spelling.

### Minor

**1. No Logging**

Unlike previous files, this one has zero output. The server starts silently. In previous files you at least had:

```go
fmt.Println("Initilizating server...")
```

Here: nothing. If you run this, you have no confirmation it's running.

**2. Function Order**

Handlers defined after main(). Go allows this, but conventional order is:

1. Imports
2. Types/Constants
3. Main function
4. Other functions

Your order (main → handlers) is unusual but not wrong.
