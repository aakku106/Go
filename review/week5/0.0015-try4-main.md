## Issues

### Critical

**1. No Error Handling on Template Operations**

```go
tem = template.Must(template.ParseFiles("./htmlFiles/cat.html"))  // Panics on error
tem.Execute(w, nil)  // Ignores error
```

Problems:

a) `template.Must()` panics if parsing fails. This crashes the entire server instead of handling the error gracefully:

```go
// Better approach:
func handleCat(w http.ResponseWriter, r *http.Request) {
    t, err := template.ParseFiles("./htmlFiles/cat.html")
    if err != nil {
        http.Error(w, "Template error", http.StatusInternalServerError)
        log.Printf("Template parse error: %v", err)
        return
    }

    if err := t.Execute(w, nil); err != nil {
        log.Printf("Template execute error: %v", err)
    }
}
```

b) `Execute()` error is ignored. If template execution fails, client gets partial HTML with no indication of error.

**2. Global Template Variable Overwritten on Each Request**

```go
var tem *template.Template  // Global

func handleCat(w http.ResponseWriter, r *http.Request) {
    tem = template.Must(template.ParseFiles("./htmlFiles/cat.html"))  // Overwrites global
    tem.Execute(w, nil)
}

func handleDog(w http.ResponseWriter, r *http.Request) {
    tem = template.Must(template.ParseFiles("./htmlFiles/dog.html"))  // Overwrites global
    tem.Execute(w, nil)
}
```

**Race condition**: If one request calls handleCat() while another calls handleDog(), they both modify the same global variable. This can cause:

- Cat template used for dog page
- Dog template used for cat page
- Corrupted template state
- Parse errors

**Correct approach**: Parse templates once at startup, not on every request:

```go
var (
    catTemplate *template.Template
    dogTemplate *template.Template
)

func init() {
    catTemplate = template.Must(template.ParseFiles("./htmlFiles/cat.html"))
    dogTemplate = template.Must(template.ParseFiles("./htmlFiles/dog.html"))
}

func handleCat(w http.ResponseWriter, r *http.Request) {
    if err := catTemplate.Execute(w, nil); err != nil {
        log.Printf("Error: %v", err)
    }
}
```

**This bug is critical.** Under concurrent load, this serves wrong pages to users.

## Security Note

You're using text/template. If you plan to render user input, switch to html/template:

```go
import "html/template"  // Auto-escapes user input
```

text/template doesn't escape HTML, so user input like `<script>alert('xss')</script>` would execute. html/template escapes this automatically.

**For now, you have no user input, so text/template is fine.** But keep this in mind for Week 6.
