### Major

**1. Functions Never Called**

```go
func call1() { ... }
func call2() { ... }
func call3() { ... }
func call4() { ... }
func call5() { ... }
```

None of these functions have `main()` or are called anywhere. File has package name `playingwithjson` but no entry point. To run this code, you'd need:

```go
func main() {
 call1()
 call2()
 call3()
 call4()
 call5()
}
```

Or rename package to `main` and add main function. Currently this is library code that demonstrates concepts but cannot execute.

**2. Inconsistent Struct Naming**

```go
type normalStruct struct { ... }
type StructWithTick struct { ... }
type struct3 struct { ... }
type struct4 struct { ... }
```

Four different naming patterns:

- `normalStruct` - camelCase, descriptive
- `StructWithTick` - PascalCase, exported
- `struct3` - lowercase + number
- `struct4` - lowercase + number

Should use consistent pattern. Either all descriptive names or all numbered:

```go
type PrivateFieldsStruct struct { ... }  // Descriptive
type PrivateFieldsWithTagsStruct struct { ... }
type MixedFieldsStruct struct { ... }
type ProperTagsStruct struct { ... }
```

Or:

```go
type example1 struct { ... }  // Numbered, all lowercase
type example2 struct { ... }
type example3 struct { ... }
type example4 struct { ... }
```

**3. StructWithTick Typo**

```go
type StructWithTick struct {
 name  string `json:"name"`
 email string `email`  // Missing "json:" prefix
}
```

Comment says:

```
email string `email`
```

Should be `json:"email"` but this is intentional to demonstrate broken tags. However, the struct name says "WithTick" when it should be "WithTags" - tick is not standard terminology:

```go
type StructWithTags struct { ... }
```

**6. Unused Variable Reassignment**

```go
func call5() {
 // ...
 response, err := json.MarshalIndent(data, "", "")
 // ...
 response, err = json.MarshalIndent(data, "", "  ")  // Reassigns response
 // ...
 response, err = json.MarshalIndent(data, "", "--->")  // Reassigns again
}
```

Demonstrates three indent styles but keeps overwriting `response`. First two results are lost. For educational purposes, should use different variable names or print all three:

```go
func call5() {
 data := struct4{...}

 // No indent
 response1, err := json.MarshalIndent(data, "", "")
 if err != nil { log.Fatal(err) }
 fmt.Println("No indent:")
 fmt.Println(string(response1))

 // Two spaces
 response2, err := json.MarshalIndent(data, "", "  ")
 if err != nil { log.Fatal(err) }
 fmt.Println("\nTwo spaces:")
 fmt.Println(string(response2))

 // Custom indent
 response3, err := json.MarshalIndent(data, "", "--->")
 if err != nil { log.Fatal(err) }
 fmt.Println("\nCustom indent:")
 fmt.Println(string(response3))
}
```

## What You Learned

1. **Public vs Private** - Only exported (uppercase) fields marshal to JSON
2. **Struct Tags** - `json:"fieldname"` controls JSON output
3. **json.Marshal** - Converts Go struct to JSON bytes
4. **json.MarshalIndent** - Formatted JSON with indentation
5. **Security Implications** - Private fields protect data from serialization
6. **Debugging Technique** - Printing raw bytes vs string conversion
7. **Interface Design** - Why encoding/json's behavior prevents data leaks
