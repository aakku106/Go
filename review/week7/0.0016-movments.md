# Code Review: 0.0016/movments.go

**File**: `0.0016/movments.go`  
**Category**: Movement Logic  
**Lines**: 18  
**Rating**: 4/10

## Overview

Five methods on Position for player movement. MoveUp/Down/Left/Right shift position by 2 pixels. Teleport sets absolute coordinates. All methods modify Position in place.

---

## Strengths

1. **Simple Implementation** - Each method does exactly one thing
2. **Pointer Receivers** - Correctly uses \*Position to modify in place
3. **Consistent Speed** - All directional moves use same delta (2 pixels)
4. **Teleport Utility** - Useful for resetting position or implementing portals

---

## Issues

### Critical

**1. Filename Typo**

```
movments.go  // WRONG: "movments" missing 'e'
```

Should be `movements.go`. This typo is visible in git commits, file explorer, imports.

**2. No Boundary Checking**

```go
func (p *Position) MoveRight() {
 p.x += 2
}
func (p *Position) MoveLeft() {
 p.x -= 2
}
func (p *Position) MoveUp() {
 p.y -= 2
}
func (p *Position) MoveDown() {
 p.y += 2
}
```

All four methods allow infinite movement. Player can move outside window bounds (0-640 for x, 0-480 for y based on main.go). Position becomes negative or exceeds screen size.

**Should clamp to bounds**:

```go
const (
 MinX = 0
 MaxX = 640
 MinY = 0
 MaxY = 480
 MoveSpeed = 2
)

func (p *Position) MoveRight() {
 p.x = min(p.x + MoveSpeed, MaxX)
}

func (p *Position) MoveLeft() {
 p.x = max(p.x - MoveSpeed, MinX)
}

func (p *Position) MoveUp() {
 p.y = max(p.y - MoveSpeed, MinY)
}

func (p *Position) MoveDown() {
 p.y = min(p.y + MoveSpeed, MaxY)
}
```

Or return error when hitting boundary.

**3. No Return Values**

```go
func (p *Position) MoveRight() {
 p.x += 2
}
```

Methods return nothing. Caller has no way to know if move succeeded or hit boundary. Should return bool or error:

```go
func (p *Position) MoveRight() bool {
 newX := p.x + 2
 if newX > MaxX {
  return false  // Hit boundary
 }
 p.x = newX
 return true  // Success
}
```

Or:

```go
func (p *Position) MoveRight() error {
 newX := p.x + 2
 if newX > MaxX {
  return fmt.Errorf("cannot move right: boundary at %f", MaxX)
 }
 p.x = newX
 return nil
}
```

### Major

**1. Magic Number (2)**

```go
p.x += 2
p.x -= 2
p.y -= 2
p.y += 2
```

Hard-coded movement delta appears 4 times. Should be constant:

```go
const MoveSpeed = 2

func (p *Position) MoveRight() {
 p.x += MoveSpeed
}
```

Easier to tune game speed by changing one constant.

**2. Teleport No Validation**

```go
func (p *Position) Teleport(x, y float64) {
 p.x = x
 p.y = y
}
```

Accepts any coordinates. Can teleport outside screen bounds or to negative positions. Should validate:

```go
func (p *Position) Teleport(x, y float64) error {
 if x < MinX || x > MaxX {
  return fmt.Errorf("x coordinate %f out of bounds [%f, %f]", x, MinX, MaxX)
 }
 if y < MinY || y > MaxY {
  return fmt.Errorf("y coordinate %f out of bounds [%f, %f]", y, MinY, MaxY)
 }
 p.x = x
 p.y = y
 return nil
}
```

**3. Incomplete Movement Set**

Has up/down/left/right but no:

- Diagonal movement (e.g., MoveUpRight)
- Smooth movement with delta time
- Acceleration/deceleration
- Move by custom delta (beyond fixed 2 pixels)

All moves are locked to 2-pixel steps. Cannot move faster or slower.

**4. No Collision Detection**

Methods only check position, not collisions with:

- Walls
- Enemies
- Obstacles
- Other players

Movement system is incomplete without collision awareness.

**5. Coordinate System Assumption**

```go
func (p *Position) MoveUp() {
 p.y -= 2  // Decreasing y moves up
}
```

This assumes screen coordinate system where:

- y=0 is top
- y increases downward
- y decreases upward

This is correct for Ebiten but implicit. Should document:

```go
// MoveUp decreases y coordinate (screen coordinates: y=0 is top)
func (p *Position) MoveUp() {
 p.y -= 2
}
```

### Minor

**1. Inconsistent Naming**

Methods follow pattern Move<Direction> but Teleport doesn't fit pattern. Could be:

```go
func (p *Position) MoveTo(x, y float64)  // Consistency
```

But Teleport is fine for explicit instant repositioning.

**2. No Comments**

No documentation. Should have:

```go
// MoveRight shifts position 2 pixels to the right
func (p *Position) MoveRight() {
 p.x += 2
}

// Teleport instantly moves to given coordinates
func (p *Position) Teleport(x, y float64) {
 p.x = x
 p.y = y
}
```

**3. Method Order**

Methods ordered: Right, Left, Up, Down, Teleport. More logical grouping:

```go
// Horizontal movement
func (p *Position) MoveRight() { ... }
func (p *Position) MoveLeft() { ... }

// Vertical movement
func (p *Position) MoveUp() { ... }
func (p *Position) MoveDown() { ... }

// Special movement
func (p *Position) Teleport(x, y float64) { ... }
```

**4. Missing Getter Methods**

Position has x and y fields (unexported in Position struct from main.go) but no getters:

```go
func (p *Position) X() float64 { return p.x }
func (p *Position) Y() float64 { return p.y }
func (p *Position) Coords() (float64, float64) { return p.x, p.y }
```

Wait - checking main.go again. Position fields are lowercase:

```go
type Position struct {
 x float64
 y float64
}
```

These are **package-private**. Movement methods are in same package so they work, but external packages cannot access Position.x or Position.y. If this becomes a library, you'll need getters.

## Final Verdict

**4/10** - Functional but incomplete. Methods work for basic movement but have zero boundary checking, no error handling, no return values, and allow player to move infinitely off-screen. Filename has typo. Magic number (2) repeated 4 times. No validation in Teleport.

**Main problems**: Filename typo, zero bounds checking, no return values, magic numbers.

**What works**: Basic directional movement, pointer receivers.

**Recommended fixes**:

1. Rename to movements.go
2. Add boundary checking with MaxX/MaxY constants
3. Return bool or error from movement methods
4. Add MoveSpeed constant to replace magic 2
5. Validate coordinates in Teleport
6. Write comprehensive tests
7. Add godoc comments
